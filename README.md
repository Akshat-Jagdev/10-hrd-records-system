# HRD Records System

Steel-plant HR & production records platform — Spring Boot + React + PostgreSQL.
Role-based access, an append-only audit trail, and a production-incentive
calculation engine. **Every row of data in this project is synthetic** — generated
by a seeded script, inspired by (and not affiliated with) a steel-plant internship.

## What it does

- **Employees & departments** — employee master data with search; PRODUCTION vs
  SUPPORT departments
- **Production records** — monthly planned/actual tonnes per department with
  computed achievement %
- **Incentive engine** — configurable schemes (threshold/ceiling per-point rate,
  grade factors); one endpoint recomputes *draft* earnings for a
  scheme+department+month; HR managers approve or reject; decided rows are
  immutable history
- **Audit trail** — every mutation records who/what/when plus full before/after
  JSON snapshots (`jsonb`), searchable by entity, user, action and time range
- **RBAC** — 4 roles (ADMIN, HR_MANAGER, VIEWER, AUDITOR) enforced at route and
  method level, with service guards for the invariants (no self-delete, never
  touch the last enabled ADMIN, no deleting data still in use)

## Stack

Java 17 · Spring Boot 3.5 (Web/JPA/Security/Validation) · Flyway · PostgreSQL 16 ·
jjwt · springdoc-openapi · JUnit 5 + Mockito + Testcontainers ·
React 19 + TypeScript + Vite · axios · hand-rolled CSS (no UI kit, no chart lib)

## Quickstart (Docker)

```bash
git clone https://github.com/Akshat-Jagdev/10-hrd-records-system.git
cd 10-hrd-records-system
docker compose up --build
```

- App: http://localhost:5173
- API + Swagger UI: http://localhost:8080/swagger-ui.html

Flyway migrates and seeds the database on first boot (V3 data is generated by
`scripts/generate_synthetic_data.py`, seeded and deterministic).

### Demo accounts

| Username | Password | Role |
|---|---|---|
| `admin` | `Admin@HRD-Demo` | ADMIN — everything, incl. user administration |
| `hr.manager` | `HrManager@HRD-Demo` | HR_MANAGER — writes business data, approves incentives |
| `viewer` | `Viewer@HRD-Demo` | VIEWER — read-only business data |
| `auditor` | `Auditor@HRD-Demo` | AUDITOR — read-only + audit trail |

The login page fills these with one click.

## Try the incentive flow

1. Sign in as `viewer` → try to add an employee → **403** (role guard works)
2. Sign in as `hr.manager` → Incentives → pick scheme *Production Incentive
   2024-25*, department *MELT*, e.g. 2025-11 → **Calculate** → drafts appear
3. Approve or reject drafts; check **Audit trail** for the recorded before/after

## Development

```bash
# backend (needs a local Postgres, or point at compose's)
cd backend && export JAVA_HOME=$(/usr/libexec/java_home -v 17)
DB_HOST=localhost DB_NAME=hrd DB_USER=hrd DB_PASSWORD=hrd \
JWT_SECRET=local-dev-secret-at-least-32-chars!! mvn spring-boot:run

mvn test      # unit tests (no DB needed)
mvn verify    # + Testcontainers integration tests (needs Docker)

# frontend
cd frontend && npm install && npm run dev   # proxies /api → :8080
```
